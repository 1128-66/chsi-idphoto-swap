# chsi-idphoto-swap

把研招网 - 学信网 App「图像采集」流程里现场拍摄的照片，在离开手机之前替换成本地准备好的证件照。

> **声明**：本工具用于**将自己的照片**交给**自己账号**的采集流程，
> 目的是避免现场抓拍效果不理想，而不是伪造身份。
> 请勿用于任何冒用他人身份或规避实名核验的场景。
> 原理与逆向分析见 [原理与逆向分析.md](原理与逆向分析.md)。

---

## 原理一句话

App 的上传鉴权（JWE 加密 + RSA 封装）全在客户端算好后由服务端校验，
无法在外部重放；但整条链路的**最后一步是 OSS PostObject 直传**，
此刻签名已经签发、服务端只校验签名本身 —— 所以在请求离开手机前
把 `multipart` 里的 `file` 部分换成本地图片即可，后续步骤自然作用于这张图。

校验成功时会比对 **OSS 返回的 ETag 与本地图的 MD5**，
一致即密码学证明"服务端存的就是本地图"。

## 环境要求

- macOS（脚本用到 `sips`、`osascript`、`open`、`ipconfig`、`lsof`）
- [mitmproxy](https://mitmproxy.org/)：`brew install mitmproxy`
- Python 3（生成二维码需要 `segno`，脚本会自动尝试安装）
- 手机与 Mac **在同一个可达网络**（通常是同一个 Wi-Fi）
- 手机上安装 **WireGuard** 客户端

## 快速开始

### 1. 启动代理

双击 **`启动换图代理.command`**。按提示选一张证件照（目前实测jpg/png/webp可用，其他格式请自行测试），
脚本会自动压缩到 1KB~1MB 的合规区间。

首次运行会生成 `wg-client.conf` 与 `wg-client-qr.png` 并自动打开二维码。

### 2. 手机连入隧道

打开手机上的 WireGuard → 添加隧道 → 扫描 `wg-client-qr.png`
（扫不动就按 `wg-client.conf` 里的内容手动新建一条隧道）→ 打开开关。

终端出现下面这行，说明手机连上了：

```
✓ 手机已连入隧道（10.0.0.x）
```

### 3. 走 App 流程

正常扫码 → 拍照 → 上传。终端里出现这行即替换成功：

```
🔒 服务端存的就是本地图 —— ETag 与本地 MD5 一致
```

### 4. 收尾

**代理不会在上传成功时自动停** —— 手机此刻仍靠这条隧道联网，
App 还要走完 `ossrs / checkst / confirm` 几步。
在 App 里看到照片预览并点确认后，回到终端按任意键收尾，
然后**关掉手机上的 WireGuard 开关**（否则手机会表现为断网）。

> 换了 Wi-Fi 之后（Mac 的 IP 变了），重新双击
> **`生成隧道二维码.command`** 出码；已在手机上建的隧道只需
> 编辑里面的 `Endpoint` 改 IP 即可，不必删掉重建。

## 常见问题

**App 抓不到流量？**
App 自带网络栈，不读系统 HTTP 代理。本方案用 mitmproxy 的
`wireguard` 模式下沉到 VPN 层解决，不要改成普通 `-p 8080` 代理模式。

**手机连不上隧道？**
1. 确认手机和 Mac 在同一个 Wi-Fi；
2. 公共 / 企业 Wi-Fi 常开**客户端隔离**，同网段也互相不通 —— 这属于网络策略，无法绕过，换个网络；
3. 确认手机上装的是最新生成的配置（`Endpoint` 里的 IP 要和 Mac 当前的局域网 IP 一致）。

**手机开着隧道就上不了网？**
隧道开启期间手机**全部**流量都走电脑，这是 `AllowedIPs = 0.0.0.0/0` 的预期行为。
收尾后关掉开关即可恢复。

**图片上传失败提示超限？**
OSS policy 限制 `content-length-range` 为 1KB~1MB。脚本会自动压缩，
但极端窄高的图片可能压不进区间，换一张即可。

## 已知限制

- 需要手机与电脑网络可达；**手机给电脑当网关**（Wi-Fi 热点 / USB 共享）时，
  电脑的出网也依赖手机，会形成环路死锁 —— 除非电脑另有一条独立外网。
- WireGuard 隧道存活期间，手机会断掉自己的直连网络。
- 只放行 OSS 主机（`--allow-hosts`），其余请求不做拦截，避免影响 App 其它功能。

## 其他平台：欢迎社区接力

目前只做了 macOS 版。好消息是**要移植的东西比看起来少** ——
`mitm_replace_photo.py`（真正干活的插件）和 `chsi_idphoto_tool.py`
都是**纯 Python、跨平台**，不需要改；需要重写的只是外面那层壳：
选图、压缩、起进程、出隧道二维码。

移植时请**别省**下面这几条，它们是这个方案能成立的关键：

- 替换失败时**掐断请求**（fail-safe）—— 放行就意味着现场拍的原图漏出去了
- `ETag == 本地 MD5` 的校验 —— 这是"服务端真存了本地图"的密码学证明
- **上传成功后不要立刻停 mitmdump** —— WireGuard 服务端就在这个进程里，
  一停手机会整机断网，App 后续步骤全走不完

有移植好的版本，欢迎提 Issue / PR。
